# A-Maze-ing

> *This is the way.*

## Description

A-Maze-ing is a modular Python maze generator and solver built to explore procedural generation and terminal-based visualization.

The application supports:

- perfect maze generation using randomized Prim’s algorithm and recursive DFS
- imperfect maze generation with controlled loop creation
- shortest-path solving using Breadth-First Search (BFS)
- deterministic generation through random seeds
- ASCII and ANSI terminal rendering
- maze export and encoding systems
- interactive terminal visualization and animations

Beyond maze generation itself, the project was designed as a reusable Python package (mazegen-*) with a clean and extensible architecture.

Particular attention was given to:

- separation of responsibilities
- modular package organization
- algorithm reusability
- maintainability and extensibility
- typed Python and documented APIs

Generation, solving, rendering, configuration handling, and export systems are intentionally isolated from one another, allowing each subsystem to evolve independently or be reused in future projects.

## Features

### Maze Generation

#### Perfect mazes

Perfect mazes guarantee:
- exactly one path between any two cells
- no cycles
- full connectivity

  

| Algorithm                                   | Description                                                       |
| ------------------------------------------- | ----------------------------------------------------------------- |
| **Randomized Prim’s Algorithm** *(default)* | Frontier-based growth algorithm producing dense and organic mazes |
| **Recursive DFS / Backtracking**            | Long corridors and classic recursive maze carving                 |

---

#### Imperfect mazes

Imperfect mazes are generated by:

- creating a perfect maze
- randomly breaking additional walls
- validating each wall removal to avoid fully-open 2x2 areas

This creates:

* Multiple possible paths
* Cycles and shortcuts
* More natural maze layouts

---

### Maze solving

* Shortest-path solving using **Breadth-First Search (BFS)**
* Path reconstruction from entry to exit
* Optional path visualization inside the rendered maze
* Directional path extraction (`N`, `S`, `E`, `W`)

## Architecture

The project is organized into independent modules:

```text
mazegen/
├── app/        # Application loop and orchestration
├── config/     # Config parsing and validation
├── io/         # File loading and export
├── maze/       # Maze structures and algorithms
├── render/     # Rendering, menu, animations
└── __init__.py
```

The architecture intentionally separates responsibilities:

- generation logic is isolated from rendering
- solving is independent from generation
- rendering does not mutate maze structures
- export systems are reusable independently

This separation allows algorithms, rendering systems, and export formats to evolve independently.

## Algorithms

### Perfect Maze Generation

#### Why Prim’s Algorithm as Default?

Randomized Prim’s algorithm was selected as the default generator because it:

- produces dense and visually rich mazes
- creates balanced branching structures
- avoids excessively long corridors
- scales well for large mazes
- naturally creates organic layouts

The algorithm works by:

- starting from a random cell
- maintaining a frontier of candidate cells
- progressively connecting frontier cells to visited cells

This guarantees a perfect maze while producing more varied structures than DFS alone.

---

#### Why DFS?

Recursive DFS / Backtracking was also implemented because it:

- is simple and elegant
- is a classic maze-generation algorithm
- produces long corridors and deep paths
- is highly readable and educational

DFS recursively visits unvisited neighbors while carving passages between cells.

---

### Imperfect Maze Generation

Imperfect mazes are generated by:

1. Building a perfect maze
2. Randomly removing additional walls
3. Validating the resulting structure to avoid overly open areas

This preserves narrow corridors while introducing loops and alternative paths.

---

### Maze Solving

Maze solving uses:

* **Breadth-First Search (BFS)**

#### Why BFS?

BFS guarantees the shortest path in an unweighted graph.

The maze grid is treated as a graph where:

* Cells are nodes
* Open passages are edges

The solver reconstructs the final path from the predecessor mapping generated during traversal.

---

## Reusability

Several parts of the project were intentionally designed to be reusable outside of the current application.

### Maze generation algorithms

The generation algorithms (`Prim` and `DFS`) are fully isolated inside the `maze` package.

This allows:
- adding new algorithms easily
- reusing the generators with different renderers
- integrating the maze engine into another application (GUI, web app, game, etc.)

---

### Solver

The BFS solver is independent from rendering and generation logic.

The solver only requires:
- a matrix of cells
- entry and exit

This makes it reusable for:
- other graph traversal problems
- different maze representations
- shortest-path visualization systems

---

### Rendering system

The rendering layer is isolated from the maze algorithms.

The same maze structure can therefore be:
- rendered in ASCII
- exported to files
- visualized graphically in the future

without modifying generation or solving logic.

---

### Export system

The export and encoding utilities are separated into the `io` package.

This allows:
- adding new export formats
- serializing mazes independently from rendering
- reusing encoding logic in external tools

---

### Modular architecture

The project uses a modular package structure where each subsystem has a single responsibility:

- `maze/` handles maze structures, generation, and solving algorithms
- `render/` handles visualization
- `config/` handles parsing and validation
- `io/` handles file input/output operations

This separation minimizes coupling and improves maintainability and extensibility.

#### Using the Maze Generator

Importing the package
```
from mazegen import MazeGenerator
```

---

#### Instantiating the generator

A generator can be created with or without a deterministic seed.
```
generator = MazeGenerator()
```

Using a custom seed:
```
generator = MazeGenerator(seed=42)
```
Using the same seed always produces the same maze structure for a given algorithm and configuration.

---

#### Generating a Maze

Generate a perfect maze (default: Prim)
```
maze = generator.generate_perfect_maze(
    width=20,
    height=15,
    entry=(0, 0),
    exit=(14, 19)
)
```
By default, the generator uses randomized Prim’s algorithm.

Generate a maze using DFS
```
maze = generator.generate_perfect_maze(
    width=20,
    height=15,
    entry=(0, 0),
    exit=(14, 19),
    algorithm="DFS"
)
```

Generate an imperfect maze
```
maze = generator.generate_imperfect_maze(
    width=20,
    height=15,
    entry=(0, 0),
    exit=(14, 19),
    break_prob=0.3
)
```

---

#### Solving a Maze
```
maze.solve_maze()
```
The shortest path is computed using Breadth-First Search (BFS).

#### Example
```
from mazegen import MazeGenerator, labyrinth_renderer

generator = MazeGenerator()

maze = generator.generate_imperfect_maze(
    width=20,
    height=15,
    entry=(0, 0),
    exit=(14, 19),
)

maze.solve_maze()
labyrinth_renderer(maze)

generator = MazeGenerator(seed=42)

maze = generator.generate_perfect_maze(
    width=20,
    height=15,
    entry=(0, 0),
    exit=(14, 19)
)

labyrinth_renderer(maze)
```

### Configuration File

Maze generation is configured through a text configuration file.

Example:

```text
WIDTH=20
HEIGHT=15
ENTRY=0,0
EXIT=19,14
OUTPUT_FILE=maze.txt
PERFECT=True
```

---

#### Configuration Options

| Key           | Description                                           |
| ------------- | ----------------------------------------------------- |
| `WIDTH`       | Maze width                                            |
| `HEIGHT`      | Maze height                                           |
| `ENTRY`       | Entry cell coordinates `(row,col)`                    |
| `EXIT`        | Exit cell coordinates `(row,col)`                     |
| `OUTPUT_FILE` | Export file path                                      |
| `PERFECT`     | Generate perfect (`True`) or imperfect (`False`) maze |

Initial plan evolved during development:

- Started with simple grid + walls representation

### What Worked Well

* Modular architecture (`Cell`, `Maze`, `Generator`, `Solver`, `Renderer`, `io`)

### Challenges

* Balancing imperfect maze generation without creating large open spaces
* Managing rendering and interaction cleanly inside a terminal application
